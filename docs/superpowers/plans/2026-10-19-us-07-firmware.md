# US-07 · Plano de implementação

> Execução sequencial nesta sessão com `executing-plans`, sem subagentes ou worktrees.

**Objetivo:** entregar o esqueleto compilável do terminal ESP32 e preparar sua demonstração MQTT no Wokwi.
**Arquitetura:** Arduino/ESP32 com módulos independentes em `firmware/src/modules/`; `main.cpp` orquestra inicialização e atualização. Só MQTT tem integração de rede nesta história; display, NFC, GPS, feedback e porta são adaptadores vazios e seguros para evolução na US-08.
**Stack:** PlatformIO Core 6.1.18, Espressif32 6.10.0, Arduino, PubSubClient 2.8.
**Especificação:** `docs/scrum/product-backlog.md`, US-07; `docs/architecture/visao-geral.md`; checklist da tarefa fornecido pelo usuário.

## Riscos e foco de revisão

- Broker indisponível: reconectar com intervalo, sem laço de espera infinita.
- WiFi perdido: reconectar sem iniciar tentativas MQTT enquanto estiver offline.
- Tópicos de outro terminal: construir sempre a partir do identificador configurado.
- Comando recebido: não acionar porta nem interpretar payload antes da US-04/08.
- Wokwi no navegador usa gateway público sem acesso ao localhost; preferir VS Code com gateway integrado. Licença/conta e Docker podem bloquear validação real e devem ser reportados, nunca simulados como sucesso.

- TDD MQTT: módulo vazio falhou em `WiFi.beginCalls == 1`; módulo real passou nos testes de offline, falha/retry, tópico/QoS, queda de WiFi, falha de inscrição e reinscrição. Doubles isolam rede; não comprovam o broker real.

- `wokwi-cli lint`: sem erros; informação `unsupported-part` para a placa ESP32 (tipo não documentado pelo catálogo do linter).
- Primeiro build falhou por pacote Arduino extraído parcialmente após timeout: `variants/esp32/pins_arduino.h` ausente; reinstalação da dependência resolveu a extração, sem contornar arquivo externo ausente no produto.
- O build real identificou uma API de timeout não disponível no Arduino-ESP32 2.x. A correção usa `WiFiClient::setTimeout(segundos)`, conforme header/implementação da dependência fixada; double alinhado à API real, regressão e build passaram.
- Verificação final local: `pio run` **SUCCESS**, RAM 44.808 bytes (13,7%), flash 746.949 bytes (57,0%); `firmware.bin` e `firmware.elf` encontrados nos caminhos do Wokwi; ambos os executáveis de teste host passaram.
