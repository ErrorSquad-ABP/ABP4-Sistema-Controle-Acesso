# DT-20 — documentar 429/503 nas operações QR

Origem: varredura Sol de 28/10. `/access-events/qr` responde `503` sem banco e `429` na requisição seguinte ao limite de 120, mas o OpenAPI declarava só `200/400/401`; `/credentials/qr/validate` responde `503` pela autenticação (`requireAuth` devolve `ServiceUnavailableError` sem `getCurrentUser`) e também não documentava.

## O que mudou

| Arquivo | Mudança |
|---|---|
| `backend/src/main/http/contract/operations.ts` | `extraErrors: [429, 503]` em `requestQrAccess` e em `validateQrCredential` |
| `docs/api/openapi.yaml` | regenerado por `npm run openapi:generate` |
| `backend/tests/unit/openapi-document.test.ts` | as duas operações entram nas listas que exigem `429` e `503` no documento |
| `backend/tests/integration/http.test.ts` | bloco `DT-20` compara a resposta HTTP real com o documento |

## Cobertura

`tests/integration/http.test.ts` → `DT-20: 429/503 documentados nas operacoes QR`:

1. App sem banco: `POST /api/v1/credentials/qr/validate` e `POST /api/v1/access-events/qr` devolvem `503`, e o documento declara `503` nas duas.
2. 121 requisições em `POST /api/v1/access-events/qr`: as 120 primeiras devolvem `503` (sem banco) e a 121ª devolve `429`; o documento declara `429` nas duas.

O teste unitário do contrato continua sendo a fonte de verdade do documento: qualquer operação fora das listas de `429`/`503` (ou com o status removido por engano) quebra o build.

## Reprodução

```bash
cd backend
npm run lint
npm run typecheck
npx vitest run tests/unit/openapi-document.test.ts tests/integration/http.test.ts
npm run openapi:generate   # sem diff pendente depois
```
