# DT-23 — teto absoluto de 100 m no QR

Origem: auditoria de 02/11/2026, US-20/RF13. Card: <https://trello.com/c/FLCzZ6TX>.

## Regra e persistência

- A política QR compara a distância com `min(radiusMeters, 100)`. Um raio legado de 200 m não libera a posição a ~150 m; um raio de 40 m continua negando a posição a ~50 m. NFC não passa por geofence.
- Raio não positivo ou não finito nega o QR, mesmo na coordenada do local.
- A migration `20261109010000_access_location_radius_limit` adiciona `AccessLocation_radiusMeters_check`: inteiro entre 1 e 100, inclusive. A anotação no Prisma documenta a CHECK, que é mantida no SQL.
- OpenAPI descreve `OUT_OF_RANGE` como fora do raio do local, com teto de 100 m. Não há endpoint de cadastro de locais hoje; a US-39 deverá validar o mesmo intervalo na entrada.

## Validação

Os testes novos falharam antes da correção: raio 200 liberava ~150 m e as sete verificações de banco aceitavam INSERT/UPDATE inválidos. Após a correção:

- `npx vitest run tests/unit/access-policy.test.ts`: 20 testes passando, incluindo 99,99 m, 100 m, 100,01 m, raio menor, legado de 200 m, raio zero/negativo/NaN/infinito e posição ausente.
- `tests/integration/access-location-radius.test.ts`: 7 testes passando contra PostgreSQL 18.4 temporário com todas as migrations, sem mocks; INSERT inválido não persiste, UPDATE inválido preserva o valor anterior, SQLSTATE `23514`.
- Suíte completa com PostgreSQL temporário + seed demo: **419/419**, nenhuma suíte ignorada (51 arquivos). A primeira execução sem seed falhou em oito testes preexistentes que exigem os dados demo; repetida com o mesmo preparo do CI, passou integralmente.
- `npm run lint` e `npm run typecheck`: aprovados.
- `npm run test:e2e`: build aprovado e **29/29**, incluindo aplicação das migrations e verificação de drift Prisma. Não usa banco remoto nem hardware.

Reprodução no banco de **teste** já migrado:

```sh
cd backend
npm run lint
npm run typecheck
npm test
npm run test:e2e
```

`npm test` executa os testes de integração quando `DATABASE_URL` aponta para banco de teste; sem a variável essas suítes são ignoradas.

## Antes de implantar

Esta alteração não executa migration nem modifica cadastros em produção. A CHECK é validada contra os dados existentes e falha se houver raio inválido. Antes de autorizar a implantação, conferir em acesso somente leitura:

```sql
SELECT id, "radiusMeters"
FROM "AccessLocation"
WHERE "radiusMeters" NOT BETWEEN 1 AND 100;
```

Se houver linhas, decidir a correção com o responsável antes de executar `prisma migrate deploy`. Não há UPDATE automático, exclusão de locais nem ampliação de raio nesta migration. O CD aplica migrations no merge: só integrar após essa conferência autorizada. Merge/deploy e teste físico pelo app continuam pendentes.
